# Talkbook 技术基线

## 技术方向

### 前端
- 首发平台：微信小程序
- 开发方案：uni-app
- 原因：启动快、开发成本低、适合快速验证 MVP

### 后端
- 方案：Node.js + TypeScript
- 责任：统一承接登录、会话、语音识别、大模型编排、支付、书稿生成

### 第三方能力
- 语音识别：讯飞 / 百度
- 大模型：豆包优先，保留可切换能力
- 支付：微信支付
- 文件存储：COS / OSS

### MVP 第一阶段落地原则
- 先跑通本地主链路，再接真实第三方能力
- ASR 第一阶段允许使用文本模拟转写
- LLM 第一阶段允许使用模板问题和 mock 书稿预览
- 支付与导出只保留产品占位，不进入当前开发闭环

## 模块划分

### 小程序端
- 首页 / 书籍类型选择
- AI 采访页
- 书稿预览页
- 用户中心
- 订单与会员页

### 服务端
- 用户与登录
- 会话与消息管理
- 音频文件上传
- ASR 抽象层
- Prompt 编排层
- 书稿生成服务
- 支付与订单服务
- 内容审核与风控

## 当前阶段说明

当前工程骨架已经初始化完成，当前任务不是重新搭架子，而是按封版文档稳定推进 MVP 主链路开发。

当前必须优先稳定的内容：

- 页面范围
- 接口契约
- 数据模型
- mock 与真实能力的替换边界
- 商业化能力的占位方式

## 下一步真正编码时的建议顺序

1. 打通首页与书籍类型选择
2. 打通会话创建、回读与多轮问答
3. 先以文字模拟转写，再替换真实录音上传
4. 打通书稿预览生成与“我的书稿”列表
5. 再接入真实 ASR / LLM
6. 最后补支付、会员、导出
